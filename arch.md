# AI Reel Generation Agent - Architecture Plan

## 1. Objective

To refactor and expand the existing Pexels-based reel generator into a comprehensive, multi-scenario AI Reel Generation Agent. The agent will integrate with Pexels, HeyGen, and Submagic APIs to create professional-quality video reels based on user-selected workflows.

## 2. Core Technologies

- **Programming Language:** Python 3.8+
- **Framework:** CrewAI
- **Video Processing:** FFmpeg (via a Python wrapper like `ffmpeg-python`)
- **APIs:**
    - **Pexels API:** For sourcing stock videos.
    - **HeyGen API:** For generating avatar-based videos.
    - **Submagic API:** For automated video editing (captions, effects, etc.).
    - **Fal AI API:** For generating audio (music and text-to-speech).
- **Environment Management:** `python-dotenv` for API keys.

## 3. High-Level Architecture

The system will be designed around a central **Dispatcher** that directs traffic to one of three **Workflow** modules. Each workflow will use a collection of **Services** to interact with external APIs and a **Video Processor** utility to handle local file manipulation.

```
+--------------------------+
|   main.py (Dispatcher)   |
| (User selects scenario)  |
+-------------+------------+
              |
              | Chooses 1 of 3
              v
+--------------------------+      +--------------------------+      +--------------------------+
| workflows/local_media.py |----->|   workflows/pexels.py    |----->|   workflows/heygen.py    |
+-------------+------------+      +-------------+------------+      +-------------+------------+
              |                             |                             |
              | Uses                        | Uses                        | Uses
              v                             v                             v
+------------------------------------------------------------------------------------+
|                                     CORE COMPONENTS                                |
|------------------------------------------------------------------------------------|
|       SERVICES                      |               UTILS                          |
|-----------------------------------|----------------------------------------------|
| - pexels_service.py               | - utils/video_processor.py (FFmpeg wrapper)  |
| - heygen_service.py               | - utils/file_uploader.py (for public URLs)   |
| - submagic_service.py             |                                              |
| - audio_service.py (Fal AI)       |                                              |
+------------------------------------------------------------------------------------+
```

### Key Architectural Challenge: Inter-Service Video Transfer

Both HeyGen and Submagic APIs require public URLs for video processing. A video generated by stitching local files or by the HeyGen API must be temporarily hosted to get a public URL before being sent to Submagic.

**Solution:** A `utils/file_uploader.py` service will be created to handle this. For development, this could use a simple file-sharing service. For production, a robust cloud storage solution (like AWS S3 or Google Cloud Storage) would be necessary.

## 4. Phased Implementation Plan

### Phase 1: Project Restructuring & Foundation (Current Phase)

**Goal:** Create a clean, scalable, and secure foundation for the new features.

1.  **Create `arch.md`:** Document the full architecture and phased plan. *(This task)*
2.  **Secure API Keys:** Move the hardcoded Pexels API key from the source code to a `.env` file. Enforce a pattern where all secrets are loaded from the environment.
3.  **Establish New Directory Structure:**
    -   Create `services/` for API clients.
    -   Create `workflows/` for scenario logic.
    -   Create `utils/` for shared tools like the FFmpeg wrapper.
4.  **Refactor `video_reel_converter.py`:** Decompose the monolithic class. Move its logic into the appropriate new modules (`services/pexels_service.py`, `services/audio_service.py`, `utils/video_processor.py`).

### Phase 2: Core Service Implementation

**Goal:** Build and test the clients for the new HeyGen and Submagic APIs.

1.  **Implement `HeygenService`:**
    -   Create `services/heygen_service.py`.
    -   Implement a function `generate_video(script, avatar_id)` that calls the HeyGen API to create a new video.
    -   Handle polling for the video generation status and retrieving the final video URL.
2.  **Implement `SubmagicService`:**
    -   Create `services/submagic_service.py`.
    -   Implement a function `edit_video(video_url)` that submits a video to the Submagic API for processing.
    -   Handle API responses and retrieve the final edited video.
3.  **Implement `FileUploader` Utility:**
    -   Create `utils/file_uploader.py`.
    -   Implement a function `upload_file(file_path)` that uploads a local video file and returns a public URL.

### Phase 3: Workflow Implementation

**Goal:** Build the end-to-end logic for each of the three user scenarios.

1.  **Implement Scenario 1 (Local Media):**
    -   Create `workflows/local_media_workflow.py`.
    -   Logic to scan a local directory for video files.
    -   Use `utils.video_processor` to trim and concatenate the files into a single video.
    -   Use `utils.file_uploader` to get a public URL for the stitched video.
    -   Use `services.submagic_service` to send the video for editing.
2.  **Implement Scenario 2 (Pexels):**
    -   Create `workflows/pexels_workflow.py`.
    -   Use `services.pexels_service` to download videos.
    -   As in scenario 1, stitch the videos, upload for a public URL, and submit to Submagic.
    -   Ensure subtitle functionality is disabled as per the requirements.
3.  **Implement Scenario 3 (HeyGen):**
    -   Create `workflows/heygen_workflow.py`.
    -   Add logic to `main.py` to allow the user to select from a list of predefined avatar IDs.
    -   Use `services.heygen_service` to generate the initial avatar video.
    -   Use `services.submagic_service` to send the generated HeyGen video URL for final editing.

### Phase 4: Integration & Finalization

**Goal:** Tie all components together into a cohesive and user-friendly application.

1.  **Build the Main Dispatcher:** Fully implement the user interface in `main.py`. This will guide the user through selecting a scenario and providing the necessary inputs (e.g., topic, avatar choice).
2.  **Centralize Configuration:** Create a `config.py` file to manage non-secret configurations like the list of HeyGen avatar IDs, default video processing settings, and local media paths.
3.  **End-to-End Testing:** Perform thorough testing of each of the three workflows to ensure they function correctly from start to finish.
4.  **Documentation:** Update the `README.md` to reflect the new architecture, features, and usage instructions.
